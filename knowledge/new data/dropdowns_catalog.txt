JGH Database: Table-Wise Dropdowns Catalog
A consolidated mapping of enums and statuses, grouped by database table.
This catalog groups every dropdown-like column (including enums, statuses, workflow tags, and category types) by
its parent table. For each table, the total number of dropdown columns is stated, followed by detailed breakdowns of
each column's SQL types, comments, stored options, and business logic behaviors.

I Table: automatic_transactions   [Contains 3 Dropdown Column(s)]
  Column: status
• SQL Type: varchar(255)
• What is it? Payout API Transaction State
• Where does it come from? (Trigger): Automatically populated via webhooks and API responses from the payment
provider gateway (Cashfree/Razorpay).
• What is its use / Business Value? Determines if payout funds successfully cleared or failed.
• Individual Value Options Breakdown:
  Value: success
What is it? Funds successfully credited to the user's bank account.
Where does it come from? Successful execution response webhook from the payment API.
What is its use? Sets the corresponding withdrawal_request.status to approved/completed, marking the transaction as final.
  Value: failed / faled
What is it? Funds transfer rejected or failed (e.g. invalid account/IFSC, insufficient gateway balance). Note: 'faled' is a
legacy vendor typo stored in the DB.
Where does it come from? Failure callback payload from the bank payout gateway.
What is its use? Flags the payout transaction for accountant review, indicating the funds were not deducted and require
retrying.
  Value: pending
What is it? Payout is currently in transit at the bank.
Where does it come from? Initial payout request confirmation payload from the provider API.
What is its use? Locks the request to prevent duplicate payout API calls while waiting for the final bank status.
  Value: rejected
What is it? Payout blocked by the gateway's risk validation or fraud checks.
Where does it come from? Gateway provider verification engine.
What is its use? Requires manual compliance review by JGH admins.
  Column: transaction_source
• SQL Type: varchar(255)
• What is it? System categorical configuration field defining the 'transaction_source' setting for the
'automatic_transactions' records.
• Where does it come from? (Trigger): Set during record creation or updated during status updates in the
'automatic_transactions' module.
• What is its use / Business Value? Used to track and filter table rows based on their 'transaction_source' values.
• Stored Values / Dropdown Options: cashfree
  Column: transfer_type
• SQL Type: varchar(255)
• What is it? System categorical configuration field defining the 'transfer_type' setting for the 'automatic_transactions'
records.
